# Local Minutes

Windows・Macで使える、日本語の会議用の録音・文字起こし・議事録ツールです。録音、Whisperによる文字起こし、話者の推定、要約は同じ端末で実行します。

## 初回セットアップ

初回はインターネットに接続して準備します。セットアップはアプリのフォルダに専用のPython環境（`.venv`）を作り、日本語対応の文字起こしモデル Whisper small（約484 MB）と、話者判定用の2つのモデル（合計約47 MB）を導入します。ダウンロードしたモデルはSHA-256で照合します。準備後はオフラインで録音、文字起こし、話者判定、要約ができます。旧版から更新する場合も、新しいアプリのフォルダでセットアップを一度実行してください。[Whisper公式](https://github.com/openai/whisper)・[sherpa-onnxの話者判定](https://k2-fsa.github.io/sherpa/onnx/speaker-diarization/index.html)

### Windows 10・11（x64）

1. **アプリを取得する。** このリポジトリの **Code → Download ZIP** からダウンロードし、エクスプローラーの「すべて展開」で書き込み可能なフォルダに展開します。Gitを使う場合は **Code** に表示されるURLでクローンしてください。
2. **Pythonを準備する。** 64ビット版のPython 3.10〜3.12を使用します。以下は3.12の例です。[Python公式ダウンロード](https://www.python.org/downloads/windows/)
3. **セットアップする。** `setup_models.py` があるフォルダでPowerShellを開き、次のコマンドを順に実行します。Windowsではイヤホンの出力を録るためのPyAudioWPatchも自動で入ります。

   ```powershell
   py -3.12 --version
   py -3.12 setup_models.py
   ```

4. **起動する。** 「準備が完了しました」と表示されたら、同じフォルダの `Start-Windows.cmd` をダブルクリックします。次回からはこの起動ファイルを開くだけです。利用中は起動時のウィンドウを開いたままにします。
5. **イヤホンで試す。** Windowsのサウンド設定で既定の出力をイヤホンにし、会議アプリのスピーカーも同じイヤホンに設定します。Local Minutesで **オンライン会議（マイク＋PC音声） → 録音を開始** を選び、ブラウザのマイク使用を許可します。自分が話したときに「自分のマイク」、相手が話したときに「相手の音声」のメーターが動けば準備完了です。録音中に出力先を変えるときは、一度停止してから新しい会議として録音を再開してください。[Windowsのループバック録音](https://learn.microsoft.com/en-us/windows/win32/coreaudio/loopback-recording)

### macOS 13以降（Apple Silicon・Intel）

1. **アプリを取得する。** このリポジトリの **Code → Download ZIP** からダウンロードし、FinderでZIPを開いて書き込み可能なフォルダに展開します。Gitを使う場合は **Code** に表示されるURLでクローンしてください。
2. **Pythonを準備する。** Python 3.10〜3.12を使用します。以下は3.12の例です。[Python公式ダウンロード](https://www.python.org/downloads/macos/)
3. **セットアップする。** ターミナルで `setup_models.py` があるフォルダに移動して、次のコマンドを順に実行します。

   ```sh
   python3.12 --version
   python3.12 setup_models.py
   ```

4. **起動する。** 「準備が完了しました」と表示されたら、Finderで `Start-Mac.command` をダブルクリックします。次回からはこの起動ファイルを開くだけです。利用中はターミナルを開いたままにします。
5. **録音を許可してイヤホンで試す。** 会議アプリの出力をイヤホンにし、Local Minutesで **オンライン会議（マイク＋PC音声） → 録音を開始** を選びます。ブラウザにはマイクの使用を、macOSにはシステム音声の録音を許可します。設定を変更する場合は **システム設定 → プライバシーとセキュリティ → 画面収録とシステムオーディオ録音**（OSによっては「画面収録」）で許可画面に表示された起動元を確認し、再起動を求められたら開き直してください。自分が話したときに「自分のマイク」、相手が話したときに「相手の音声」のメーターが動くことを確認します。[Appleの録音許可ガイド](https://support.apple.com/ja-jp/guide/mac-help/mchld6aa7d23/mac)

いずれのOSでも、画面が自動で開かない場合は起動ウィンドウに表示されたURLを同じ端末のChromeまたはEdgeで開きます。旧版を使用中の場合は先に終了してください。会議履歴は同じ端末の共通の保存先から読み込みます。

## 日本語の文字起こし精度を上げる

固有名詞、曜日、金額などの聞き取りを改善したい場合は、より大きな **Whisper large-v3-turbo**（約1.62 GB）を選べます。初回セットアップ時または後から、アプリのフォルダで次のコマンドを実行します。

| OS | 話者判定モデルとlarge-v3-turboを導入するコマンド |
| --- | --- |
| Windows（PowerShell） | `py -3.12 setup_models.py --asr turbo` |
| macOS（ターミナル） | `python3.12 setup_models.py --asr turbo` |

既存のWhisperモデルを引き続き使う場合は、上記コマンドで `--asr turbo` の代わりに `--speakers-only` を指定すると、追加の文字起こしモデルを取得せずに話者判定を導入できます。

導入後にアプリを起動し、**ローカル設定 → Whisper モデル（.pt）** で `large-v3-turbo.pt` を選択して保存します。モデルを指定したことがない場合は導入済みのturboが自動で選ばれます。smallを選んだ場合も、日本語の候補文を比較し、認識の確度が低い区間を再推論します。無音やごく小さな定常ノイズだけの区間は認識から除きます。

過去の会議は履歴から開き、**この音声で新しく解析** を押すと、現在のモデルで文字起こしと話者判定を最初から実行します。結果は別の議事録として保存され、元の議事録と手動で付けた名前が残ります。

## オンライン会議を録音するとき

**録音を停止**すると、マイクとPC音声をそれぞれ文字起こしして発言時刻順に並べます。マイクの発言には「自分」が付きます。PCから聞こえる参加者は声をもとに「話者A」「話者B」などに分かれます。人数を指定するときは、自分を含めた話者数を録音前に入力します。

PC音声には通話以外の動画や通知音も入ります。自分のマイクはLocal Minutesが個別に開くため、会議アプリでミュートしていてもLocal Minutesには入力されます。

## 誰が何を言ったかを確認する

1. 会議名を入力します。人数が分かっている場合は「会議の話者数」で1〜12人を指定できます。初期値は自動推定です。
2. **録音を開始**を押してブラウザとOSのマイク使用を許可します。停止すると、音声を保存し、文字起こし、話者推定、要約を順に実行します。録音済みのファイルは「ファイルを選択」から取り込めます。
3. **文字起こし**を開きます。同じ人が後でもう一度発言すると、同じ会議内では同じ話者タグが付きます。各発言の時刻をクリックすると、その位置から音声を再生できます。
4. **話者を編集**を開き、聞き取った声と照合して「話者A」に「田中さん」などの名前を入力します。同じタグのすべての発言に名前が付きます。一部の発言だけ誤っている場合は、その行の話者を選び直します。推定から漏れた人は「話者を追加」で登録できます。
5. **保存**すると、文字起こしと要約の出典に変更が反映されます。**Markdown 保存**で、最新の話者名とタイムスタンプ付きの要約・全文を1つのファイルに書き出せます。

学習済みのpyannoteモデルが声のある区間を検出し、3D-Speakerのモデルが会議全体で声の特徴が似た区間をまとめます。その結果をWhisperの単語時刻に照らし、発言の途中で話者が交代した場合もタグを分けます。複数の声が同じ音声に重なり発言者を特定しにくい箇所は「話者未設定」になることがあります。短い相づちや似た声では誤判定もあります。タグは会議ごとに付け、必要に応じて利用者が氏名を登録します。

## 入力音声

対面会議ではマイクをモノラルPCM WAVで録音します。オンライン会議ではマイクを `mic.wav`、PC音声を `remote.wav` として別々に記録し、停止後に両方を同期した再生用の `audio.wav` を作ります。自分と相手が同時に話した場合も、それぞれの入力で認識できた発言が残ります。相手同士の声は同じ入力にまとまるため、複数人が同時に話す場面では判定が不確かになります。

PCM WAVの取り込みは標準構成で使えます。M4A・MP3・MP4・AAC・FLAC・OGG・WebM・AIFFなどには、同じ端末のFFmpegが必要です。起動時のPATH、または使用するPython実行ファイルと同じフォルダに配置します。取り込みファイルとマイク録音はそれぞれ2 GiBまでです。オンライン会議はPC音声と再生用音声の保存にも容量を使います。[FFmpeg公式](https://ffmpeg.org/download.html)

## 要約の方式

標準設定では、決定や期限に関係する語、話題との関連、発言の重複を考慮して、重要な発言を時刻・話者付きで抽出します。追加モデルが不要で、元の言い回しを確認できます。

文章を生成する要約を使う場合は、初回準備後、次のコマンドで同じPython環境に `llama-cpp-python` をインストールします。CPU向けの事前ビルドを使う例です。コマンドはアプリのフォルダで実行します。

**Windows（PowerShell）**

```powershell
.\.venv\Scripts\python.exe -m pip install --only-binary=llama-cpp-python --extra-index-url https://abetlen.github.io/llama-cpp-python/whl/cpu llama-cpp-python
```

**Mac**

```sh
.venv/bin/python -m pip install --only-binary=llama-cpp-python --extra-index-url https://abetlen.github.io/llama-cpp-python/whl/cpu llama-cpp-python
```

システムのPythonで起動する場合は、その環境にインストールしてください。対応するCPU・Python版のバイナリが配布されていない場合は、公式のビルド手順を参照してください。[llama-cpp-python公式インストール手順](https://llama-cpp-python.readthedocs.io/en/latest/#installation)

日本語対応のチャット用GGUFを端末内に用意し、会議を処理する前に **ローカル設定 → 生成要約モデル** へ絶対パスを入力します。例としてQwen2.5-3B-InstructのQ4_K_M版があります（約2.1 GB）。生成した要点には根拠の発言を添えます。モデルを読み込めない場合、または引用を照合できない区間では抽出に切り替え、議事録にその旨を表示します。[Qwen公式GGUF](https://huggingface.co/Qwen/Qwen2.5-3B-Instruct-GGUF/blob/main/qwen2.5-3b-instruct-q4_k_m.gguf)

## 保存先と終了

| OS | 会議データの既定の保存先 |
| --- | --- |
| Windows | `%LOCALAPPDATA%\LocalMinutes` |
| Mac | `~/Library/Application Support/LocalMinutes` |

ローカル設定で実際の保存先を確認できます。会議ごとのフォルダに音声、認識原文、時刻・話者付きの文字起こし、要約を保存します。話者名と手動の割り当ては `meeting.json` に保存します。修正済みの内容を外部のエディタで読むときは画面の **Markdown 保存** を使ってください。

アプリは `127.0.0.1` にのみ接続を受け付けます。画面は起動時に発行されるランダムな鍵でこの端末の処理と通信します。会議データは端末上の通常のファイルとして保存されます。バックアップや同期の対象はOS側の設定に従います。機密情報を扱う場合は、書き出し先も端末内のフォルダを選んでください。

終了は録音と議事録作成が終わってから、ターミナルで **Ctrl+C** を押します。録音済みの会議は次回起動時に履歴から開けます。
